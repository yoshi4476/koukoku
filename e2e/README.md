# ADGRID E2E 回帰スイート

稼働中のサーバに対して主要フローと**提供先(clientScope)分離**を検証する統合テスト。
純関数のユニットテスト (`apps/api` vitest 54件) を補完し、API境界・認可・UI描画を横断で守る。

## 前提
- API が `http://localhost:4000`、Web が `http://localhost:3000` で起動していること
- Python の Playwright が導入済み (`pip install playwright && playwright install chromium`)
- デモデータが投入済み (seed)。デモ: 自社 `demo@adgrid.jp` / 提供先 `clienta@adgrid.jp` (共通 `demo-pass-2026`)

## 実行
```bash
python e2e/run_e2e.py
```
全ケース成功で exit 0、1件でも失敗で exit 1 (CI 連携可)。

## 検証内容 (18ケース)
- **自社フロー**: ログイン / プロジェクト一覧 / 業種特化クリエイティブ生成(4案・各フィールド) / 採用→制作物化
- **提供先分離**: スコープ保持 / 自クライアントのみ可視 / 他クライアントは404 / リセラー等ホワイトリスト外は403 / プロジェクト作成403 / フィードバック送信201
- **UI スモーク**: ホームの自律運用サイクルボード / プロジェクトの運用サイクル5フェーズ / 配信設定の業種別導線設計 / ページ例外なし

> 注: 本スイートは demo データを一部変更する (クリエイティブ採用で制作物が増える)。
> クリーンに戻すには seed を再投入する。
